# 部署手册 · 安矿智析

本文档覆盖两套部署形态：**PC 服务器部署**（完整平台）与 **RISC-V 边缘端部署**
（Milk-V Duo 离线推理）。快速上手可直接看仓库根目录 `README.md` 第 3 节。

## 一、PC 服务器部署（完整平台）

### 1.1 硬件建议

| 场景 | 配置 |
| --- | --- |
| 开发验证 | 8 核 CPU / 16 GB 内存 / 无 GPU（可跑，速度较慢） |
| 生产推荐 | 8 核 CPU / 32 GB 内存 / NVIDIA GPU（≥6 GB 显存，CUDA 11.8+） |

### 1.2 前置依赖：FFmpeg（必需）

FFmpeg 用于按帧序号无损切片与 H.264 规范化转码，缺它无法完成剪辑。

```bash
# Ubuntu / Debian
sudo apt update && sudo apt install -y ffmpeg

# Windows：下载 https://www.gyan.dev/ffmpeg/builds/ 的 essentials 版本，
# 解压后把 ffmpeg.exe 所在目录加入 PATH，或把 ffmpeg.exe 直接放到 backend/ 下。
ffmpeg -version
```

`backend/ai_engine.py` 的 `_get_ffmpeg_path()` 按以下顺序探测可执行文件：
`PATH 中的 ffmpeg` → `/usr/bin/ffmpeg` → `/usr/local/bin/ffmpeg` →
`/opt/homebrew/bin/ffmpeg` → `./ffmpeg` → `./backend/ffmpeg`。

### 1.3 改进版检测框架（后端与训练都依赖）

后端推理要用到 `C3k2_Faster_EMA`、`TripletAttention`、`Detect_Efficient` 等自定义
模块，这些只存在于仓库自带的框架里。**先装它，且不要再装 PyPI 上的 ultralytics**，
否则后者会覆盖前者，`best.pt` 加载时报 "unknown module" 类错误。

```bash
# 在仓库根目录执行
pip install -e framework/
python -c "from ultralytics import YOLO; print('framework ok')"
```

### 1.4 后端

```bash
cd backend
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python app.py
# 成功标志：控制台输出 "煤矿系统后端 V2.0 已启动: http://0.0.0.0:2800"
# 健康检查：curl http://localhost:2800/api/health
```

要点说明：

- **端口固定 2800**（`app.py` 末尾 `app.run(host='0.0.0.0', port=2800)`）。
  前端 `src/api/index.js` 中的 `API_BASE_URL` 必须与之一致；若改端口，两边同步修改。
- **首次启动自动建库**：程序启动时执行 `db.create_all()`，生成 SQLite 数据库与
  数据表（钻孔台账、地点、摄像仪、识别记录、用户等），无需手工迁移。
- **默认权重**：`ai_engine.py` 默认加载 `backend/zzbest.pt`；如需换成自己训练
  的权重，修改 `AIEngine(...)` 初始化时的 `weights_path` 参数即可。
- **视频路径**：默认指向 `backend/raw_videos/processed`；可用环境变量
  `VIDEO_ROOT` 覆盖，便于容器化或挂载大容量存储。
- **生产部署**：AI 推理为计算密集型任务，请使用**单 worker + 队列**方式
  （`gunicorn -w 1 -b 0.0.0.0:2800 app:app --timeout 600`），避免多进程重复
  加载模型导致显存 / 内存溢出。超过 4 路并发建议改用 Celery/RQ 拆分推理服务。

### 1.5 前端

```bash
cd frontend
npm install
npm run dev        # 开发预览，默认 http://localhost:5173
npm run build      # 生产构建，产物在 dist/
```

`backend/app.py` 当前**不托管静态文件**，`dist/` 需要单独发布：

- **Nginx 静态托管**（推荐）：API 反向代理到后端 2800 端口；
- **Vite 预览**：`npm run preview`（仅临时演示用）。

Nginx 关键配置：

```nginx
server {
    listen 80;
    root /var/www/coalmine/dist;
    location / { try_files $uri $uri/ /index.html; }
    location /api/ { proxy_pass http://127.0.0.1:2800; proxy_read_timeout 600s; }
    location /api/video/ { proxy_pass http://127.0.0.1:2800; }   # 切片视频流
    location /api/analysis/feed/ { proxy_pass http://127.0.0.1:2800; }  # MJPEG 实时画面
    client_max_body_size 2G;                                     # 允许大视频上传
}
```

### 1.6 首次使用

1. 浏览器访问前端，**在登录页点击"注册"**创建账号。系统无内置默认管理员，
   安全策略要求：用户名须**字母+数字组合**，密码 **>6 位且含字母与数字**，
   不符合规范会被后端拦截并返回 400。
2. 进入**基础数据管理** → 录入施工地点与摄像仪（录入摄像仪时自动拼接 RTSP 地址）。
3. 进入**工序智能分析** → 上传钻场监控录像，设置"归档重命名"名称与跳帧阈值
   （1–30，默认 3），提交任务。
4. 任务完成后点**查看结果** → 自动跳转视频归档库并定位切片。
5. 进入**钻孔业务管理** → 新建台账，把切片与钻孔编号绑定，形成"一孔一档"。

## 二、RISC-V 边缘端部署（Milk-V Duo）

适用场景：井下带宽受限、要求本地闭环的钻场。检测在板端完成，仅上传结构化结果。

### 2.1 硬件与镜像

- 开发板：Milk-V Duo / Duo 256M / Duo S（256 MB 版可运行，建议 512 MB）
- 系统：官方 Debian 镜像（buildroot 亦可，需自带 Python3）

### 2.2 安装

```bash
# PC 侧准备：把 deploy/ 与 ONNX 权重一并拷到板端
scp -r deploy/ weights/best11_ir9.onnx root@<board-ip>:/root/coalmine/

# 板侧执行
ssh root@<board-ip>
cd /root/coalmine
bash setup_board.sh     # 安装 python3 / pip / numpy / opencv-python-headless / onnxruntime
```

`setup_board.sh` 会自动探测 Python 并安装最小依赖集；onnxruntime 若 pip 源不可用，
可使用板端预编译 wheel（见脚本内注释）。

### 2.3 推理

可用参数：`--model` `--source` `--output` `--conf`（默认 0.5）
`--iou`（默认 0.45）`--img-size`（默认 640）`--frame-skip`（默认 2）
`--serve` `--port`（默认 8080）

```bash
# 图片
python board_infer.py --model best11_ir9.onnx --source test.jpg --output ./output

# 视频（跳帧 2，输出结构化 JSON）
python board_infer.py --model best11_ir9.onnx --source drill.mp4 \
    --output ./output --frame-skip 2

# HTTP 服务模式（供井下网关轮询结果）
python board_infer.py --model best11_ir9.onnx --serve --port 8080
```

输出 JSON 结构：

```json
{
  "frame": 123,
  "timestamp": 4.1,
  "detections": [
    {"class": "signage", "conf": 0.93, "box": [x1, y1, x2, y2]}
  ]
}
```

### 2.4 摄像头实时模式

```bash
python board_camera.py --model best11_ir9.onnx --source 0 --frame-skip 3
```

检测结果经串口 / 网口上报，`pc_client.py` 在 PC 端接收并可视化；
`serial_connect.py` 负责串口连接，`fix_driver.py` 用于修复 UVC 摄像头驱动。

### 2.5 常见问题

| 现象 | 处理 |
| --- | --- |
| 推理内存不足 | 换用 512 MB 版 Duo，或增大 swap；把 `--img-size` 降到 416 |
| USB 摄像头无画面 | 执行 `python fix_driver.py` 修复 UVC 驱动，确认 `/dev/video0` 存在 |
| OpenCV 导入失败 | 确认安装的是 `opencv-python-headless`（无 GUI 依赖） |
| 结果上报中断 | 检查串口波特率（默认 115200）与网口防火墙 |

## 四、常见问题（平台侧）

| 现象 | 处理 |
| --- | --- |
| 提交任务后立即失败 | 检查 FFmpeg 是否可用（`ffmpeg -version`）；检查 `raw_videos/` 写权限 |
| 前端接口全部报错 | 确认后端 2800 端口已启动，且 `src/api/index.js` 的 `API_BASE_URL` 一致 |
| 视频无法播放 / 拖动卡顿 | 切片需为 H.264 + faststart；检查 Nginx 是否正确代理 `/api/video/` |
| 中文叠加文字显示为方框 | 确认 `fonts/NotoSansSC-Regular.otf` 存在；程序会回退到系统 SimHei，再回退到 PIL 默认字体 |
| 并发任务变慢 | 单机超过 4 路并发时增大跳帧阈值，或改为多机调度 |
